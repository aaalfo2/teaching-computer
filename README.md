سناریوی ۸۰ دقیقه‌ای کلاس GitHub

🎯 خروجی نهایی کلاس

در پایان جلسه، هر دانش‌آموز باید یک Repository شخصی داشته باشد، داخلش یک README.md ساخته باشد و حداقل ۲ Commit انجام داده باشد.


---

بخش اول — شروع کلاس | ۰ تا ۱۰ دقیقه

دقیقه ۰ تا ۳ — سؤال شروع

کلاس را با این سؤال شروع کن:

> «بچه‌ها، فرض کنید امروز یک پروژه خیلی خوب درست می‌کنید و فایلش رو روی کامپیوترتون ذخیره می‌کنید. فردا میاید و یک تغییر بزرگ توش میدید، ولی پروژه خراب میشه. چطوری می‌تونیم برگردیم به نسخه دیروز؟»



چند نفر جواب می‌دهند.

بعد بگو:

> «حالا اگر پروژه‌مون رو یک ماه تغییر بدیم، چطور بفهمیم هفته پیش چه شکلی بوده؟»



بعد:

> «امروز می‌خوایم با ابزاری آشنا بشیم که دقیقاً برای مدیریت همین تغییراته.»




---

دقیقه ۳ تا ۷ — Git چیست؟

روی تخته بنویس:

Git = ثبت و مدیریت تغییرات پروژه

و بگو:

> «Git مثل یک دوربین برای پروژه‌مونه. هر بار که یک تغییر مهم انجام می‌دیم، می‌تونیم از وضعیت پروژه یک عکس بگیریم و بعداً ببینیم چه اتفاقی افتاده.»



این تشبیه برای این سن خیلی خوب جواب می‌دهد.


---

دقیقه ۷ تا ۱۰ — GitHub چیست؟

حالا بگو:

> «خب، Git پروژه ما رو مدیریت می‌کنه. اما اگر بخوایم پروژه‌مون رو روی اینترنت نگه داریم، با دوستامون به اشتراک بذاریم یا از یک کامپیوتر دیگه بهش دسترسی داشته باشیم چی؟»



بعد:

> «اینجاست که GitHub وارد میشه.»



روی تخته:

Git → مدیریت تغییرات

GitHub → نگهداری و همکاری روی پروژه‌ها

و تأکید کن:

> «Git و GitHub دقیقاً یکی نیستند.»




---

بخش دوم — ورود به GitHub | ۱۰ تا ۲۰ دقیقه

دقیقه ۱۰ تا ۱۲

خودت روی پروژکتور GitHub را باز کن.

بگو:

> «امروز هرکدوم از شما قراره حساب شخصی خودتون رو داشته باشید. از این به بعد پروژه‌هایی که خودتون می‌سازید می‌تونن توی همین حساب قرار بگیرن.»



دقیقه ۱۲ تا ۲۰

بچه‌ها وارد حسابشان شوند.

اینجا خودت هم‌زمان قدم‌به‌قدم جلو برو.

اگر بعضی‌ها مشکل ورود دارند، کلاس را متوقف نکن. بگو:

> «اگر کسی مشکل ورود داره، فعلاً دستش رو بالا بگیره. بقیه با من جلو بیان.»



این نکته خیلی مهم است؛ چون ممکن است یک نفر رمز عبورش را فراموش کرده باشد و ۱۵ دقیقه کل کلاس معطل شود. 😄


---

بخش سوم — ساخت اولین Repository | ۲۰ تا ۳۵ دقیقه

دقیقه ۲۰ تا ۲۳

روی پروژکتور:

New Repository

اسم را بگذار:

my-first-project

بعد توضیح بده:

> «Repository یا مخزن، جاییه که فایل‌های مربوط به یک پروژه رو نگه می‌داریم.»



بعد بگو:

> «فرض کنید این Repository، کوله‌پشتی پروژه ماست. فایل‌های پروژه‌مون رو داخلش می‌ذاریم.»




---

دقیقه ۲۳ تا ۲۷

یک README.md بساز.

مثلاً:

# My First GitHub Project

Hello!
My name is Ali.

I am learning GitHub.

بعد توضیح بده:

> «این فایل README معمولاً اولین چیزی هست که وقتی کسی پروژه ما رو می‌بینه، باهاش مواجه میشه.»




---

دقیقه ۲۷ تا ۳۰ — اولین Commit

اینجا یک لحظه مکث کن و بگو:

> «حالا می‌رسیم به یکی از مهم‌ترین کلمات امروز: Commit.»



روی تخته:

Commit = ثبت یک تغییر

بعد بگو:

> «من الان این تغییر رو انجام دادم. با Commit به Git می‌گم: این تغییر رو به عنوان یک مرحله از پروژه ذخیره کن.»



حالا Commit کن.

بعد به بچه‌ها بگو:

> «حالا نوبت شماست.»




---

دقیقه ۳۰ تا ۳۵

همه باید:

1. Repository بسازند.


2. README ایجاد کنند.


3. اولین Commit را انجام دهند.



تو در این مرحله بیشتر دور کلاس بچرخ تا پشت کامپیوتر خودت بمانی.


---

بخش چهارم — جادوی GitHub 😄 | ۳۵ تا ۵۰ دقیقه

این قسمت به نظرم مهم‌ترین قسمت جلسه است.

بگو:

> «حالا می‌خوایم ببینیم چرا Commit واقعاً جالبه.»



در README خودت یک جمله اضافه کن:

I love programming!

Commit کن.

بعد یک جمله دیگر اضافه کن:

I want to become a programmer!

دوباره Commit کن.

حالا برو به History.

بگو:

> «ببینید! من الان سه مرحله مختلف از پروژه‌ام رو دارم.»



روی تخته:

Commit 1
   ↓
Commit 2
   ↓
Commit 3

بعد بگو:

> «این یعنی اگر پروژه من بزرگ بشه، می‌تونم بفهمم در هر مرحله چه تغییراتی انجام شده.»



یک سؤال از بچه‌ها:

> «به نظرتون اگر اشتباهی چیزی رو پاک کنیم، داشتن History چه کمکی می‌تونه بهمون بکنه؟»



بگذار خودشان جواب بدهند.

این خودش یک آموزش بسیار ارزشمند درباره امنیت دیجیتال است.

بخش هفتم — نمایش پروژه‌ها | ۷۰ تا ۷۷ دقیقه

حالا ۳ یا ۴ دانش‌آموز را انتخاب کن.

بگو:

> «بیا پروژه‌ات رو به بقیه نشون بده.»



از هر نفر فقط این سه سؤال را بپرس:

۱. Repository کجاست؟

۲. README کجاست؟

۳. Commitهای تو کجا هستند؟

اگر یکی جواب داد، تشویقش کن.

حتی اگر پروژه‌اش خیلی ساده است.

هدف امروز یادگیری و اعتمادبه‌نفس است، نه پروژه حرفه‌ای.

بخش هشتم — جمع‌بندی | ۷۷ تا ۸۰ دقیقه

در آخر چهار کلمه روی تخته بنویس:

Git
GitHub
Repository
Commit

بعد از خود بچه‌ها بپرس:

> «Git چیه؟»



> «GitHub چیه؟»



> «Repository چیه؟»



> «Commit چیه؟»



و در پایان بگو:

> «امروز شما اولین پروژه GitHub خودتون رو ساختید. از این به بعد می‌تونیم پروژه‌های خیلی جدی‌تری با هم بسازیم.»



و اینجا می‌توانی یک جمله هیجان‌انگیز برای جلسه بعد بگویی:

> «جلسه بعد می‌خوایم یاد بگیریم چطور چند نفر می‌تونن هم‌زمان روی یک پروژه کار کنن، بدون اینکه کار همدیگه رو خراب کنن.»



این جمله ذهنشان را برای Branch و Pull Request آماده می‌کند.

⭐ یک نکته آموزشی خیلی مهم

برای این سن، زیاد توضیح نده؛ زیاد انجام بده.

یعنی به‌جای اینکه ۱۰ دقیقه درباره Commit سخنرانی کنی:

۲ دقیقه توضیح → ۵ دقیقه انجام دادن → ۲ دقیقه سؤال → دوباره تمرین

این ریتم برای بچه‌های هفتم تا نهم خیلی بهتر جواب می‌دهد.

و اگر فقط یک چیز قرار باشد از این جلسه در ذهنشان بماند، من دوست دارم این باشد:

> «هر بار که یک تغییر مهم در پروژه‌ام انجام می‌دهم، می‌توانم آن را با یک Commit ثبت کنم.»



این پایه‌ی خیلی خوبی برای جلسات بعدی Git و GitHub است.
